|---|---|---|
| D1 | **Mock transport now, real Claude later** | Operator choice. Keeps API cost/keys out of v1; works under plain `pnpm dev` (which doesn't serve `api/`). The mock emits the *same* `AkuEvent` shape as the future real transport → drop-in. |

| D4 | **Transport = Strategy interface; tools = Map registry** | DIP (hook depends on interface) + Rule 6 (no `switch` on tool name). Makes the real-model swap and new-tool additions local, low-risk changes. |

| D6 | **Launcher composed from `IconButton`+tokens, not a new FAB primitive** | One consumer; a FAB primitive isn't earned yet. Reuse over Grow. |
| D7 | **Access control deferred (personal/dev)** | Operator choice; v1 has no real endpoint so no live cost surface. Hardening is a hard gate before the real route ships (RISK_NOTES R1). |
| D8 | **Mock intent matching is shallow keyword heuristics** | It only needs to demonstrate read + edit end-to-end; the real model replaces the "decide which tool" logic, keeping the same tool registry. |
| D9 | **Discoverability iteration: labeled pill + reposition above the thumbnail strip + first-run coachmark** | Launcher was a bare 48px icon at `bottom-4 right-4`, buried behind the bottom ThumbnailPanel strip (z-46). Fix: a labeled accent pill (icon + "아쿠") raised to `bottom-28` (clears the strip), panel raised to match, + a one-shot `OnboardingCoachmark` (persistKey `aku-intro`) to actively invite the first use. All reuse/compose (no new DS primitive). |
| D10 | **Delay the coachmark ~800ms after mount** | Mounting it during initial load let canvas focus/pointer events trip Radix's outside-dismiss → it closed + persisted before being seen (flash-and-vanish). Gating behind a short settle delay fixes it; the e2e locks first-show + persisted-silence-on-reload. |
| D11 | **Movable + resizable, persisted; default top-left** | Per request. `useAkuGeometry` holds {x,y,w,h} in localStorage (`weave.aku.geometry`), default top-left below the header. Launcher is drag-or-tap (4px threshold → drag relocates, tap opens); panel drags by its header title cluster and resizes from a bottom-right grabber. All clamped to the viewport (≥56px always grabbable) + persisted across collapse/expand/reload. Reuse/compose only — no new DS primitive. e2e covers default-top-left, drag+persist, resize. |
| D12 | **Agent emits theme `var(--token)` for STRUCTURAL color; literal hex only for fixed-meaning hues** | Per request — agent-generated designs should re-skin when the user switches the editor theme. The theme-reactive rail already shipped (WI-040: `theme-tokens.ts` + ColorPicker theme row store `var(--*)`, CSS resolves per `[data-theme]`); the only gap was the agent didn't know the vocabulary, so it emitted fixed hex → theme-inert decks. Fix is prompt-only: `weave-capabilities.ts` `WEAVE_DOMAIN_KNOWLEDGE` §4 (cached, full token vocabulary + role split) + a tight `WEAVE_TASK_PRIMER` reminder. Scope = **structural color only** (bg/text/accent/surface + 4 domain accents as a categorical palette + token-stop gradients); literal hex reserved for brand/data-bound/photo/status colors whose hue is the meaning. MOOD is redirected from "bespoke hex palette" → layout/typography/structure + the theme itself supplies hues. No StyleRef conversion needed on the add/update path: a raw `var()` string renders and re-resolves already (StyleRef only adds per-slide cascade override, out of scope). Verified: tsc clean + aku agent unit tests green; render path proven by WI-040. |
| D13 | **Theme adherence hardened + media usage strengthened (prompt)** | Follow-up to D12: "theme color not applying" was diagnosed as PROMPT ADHERENCE, not a render bug — the rail works (text via inline style, shape fill via SVG presentation attr both resolve `var()` per `[data-theme]`; `var(--bg-page)` luminance probes as "dark" but stays coherent because the theme supplies matching text). The agent was still picking literal hex for the most visible surface (the slide BACKGROUND). Fix: made tokens the explicit DEFAULT in `WEAVE_TASK_PRIMER`, called out the slide background specifically, and labeled literal hex as "theme-inert / the #1 reason theme isn't applying". Also added a USE MEDIA & SHAPES bullet so the agent reaches for image/video/shape/qr (incl. source-less placeholders) to maximize expression instead of text-only slides. Prompt-only; reaches the model via the client-sent capabilities/primer (no server redeploy). |
| D14 | **Source-less VIDEO renders a placeholder (poster cover or icon) + carries an `alt` description** | Per request, mirroring the image source-less placeholder (WI-076). `VideoBlock`: no `src` → if `poster` set, render it as a static COVER IMAGE + play badge; else a neutral box with a play glyph + `alt` as centered caption — never an empty black `<video>`. `alt` (a short clip description, e.g. "제품 데모 영상") added as a **weave-local** extension of `VideoAttrs` (`& { alt?: string }`) + seeded in `domain-kinds.ts` — NOT a core change, because `@agocraft/core` is vendored as prebuilt tarballs (a rebuild/re-vendor is out of scope) and the serializer preserves the extra attr via `onUnknown: "preserve"`. Agent docs updated (`weave-capabilities.ts` video itemKind + `VIDEO_ATTRS_NOTE` in command-schemas). Verified: new `video-placeholder.spec.ts` e2e (icon+caption and poster-cover, both assert zero `<video>`), 350 document unit tests + media-src-dialog e2e green, tsc clean. |
| D15 | **Content text is theme-reactive by default + per-ROLE token mapping is mandatory in the prompt** | Per request ("all palette-applicable meaningful content should follow the theme — title text, body text, emphasis color"). Two levers: (1) STRUCTURAL — the text default color in `domain-kinds.ts` (and the agent-advertised default in `weave-capabilities.ts`) changed from the fixed `#1f2933` to `var(--text-default)`, so ANY text created without an explicit color re-skins per theme AND adapts to the canvas bg-tone (the `data-canvas=document`/`data-bg-tone` machinery already flips `--text-*`). (2) PROMPT — the `text` itemKind's color guidance was the weak link (it said only "color (CSS color)", contradicting the global token rule); it now mandates a role→token map: title/heading → var(--text-strong), body → var(--text-default), secondary → var(--text-soft), caption → var(--text-muted), emphasized word/number → var(--accent)/-strong. A single default can't express the title/body/emphasis hierarchy, so the per-role token assignment stays the agent's job; the default is the safety net. QR left literal on purpose (scannability needs fixed contrast). Verified: `text-item.spec.ts` updated + green, 357 unit tests, tsc clean. |
| D16 | **Agent is told the theme registry (static) + the currently-active theme (per-task)** | Per request ("telling the agent the theme list or the current palette would help"). Static: `WEAVE_DOMAIN_KNOWLEDGE` §5 lists all registered themes grouped by tone, DERIVED from the design-system `THEMES` registry (so it can't drift) + mood→theme recommendations; the agent can suggest a theme but cannot switch it (the user does). Dynamic: `use-aku-agent.ts` injects a `[현재 테마]` line (label + dark/light tone + hint, read off `<html data-theme>`) into each task so the agent knows the live surface — it uses the tone to keep LITERAL colors (charts/status) readable, while structural color stays in var(--token) and follows whatever theme is active. No resolved hex values are sent on purpose (that would invite theme-inert literals). Verified: tsc clean, 357 unit + aku agent units green. |
