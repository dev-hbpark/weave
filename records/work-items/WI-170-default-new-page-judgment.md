# WI-170 — 페이지-바운드 에이전트의 기본 판단: 명시 없으면 새 페이지에서 작업

- Status: DONE (2026-06-11)
- Origin: 사용자 요청 — "이전 아이템 또는 프레임 또는 슬라이드의 수정 및 변경에
  대한 요청이 별도로 없다면 기본적으로 새로운 페이지 또는 슬라이드(프레임)
  생성후 해당 영역에서의 디자인 작업으로 판단하도록 강화해줘"
- Related: WI-169(페이지생성 레일 패리티 — 도구 채널), DR-115 §8(activatesPage),
  WI-168(AgentSurfacePolicy)

## 판단 근거 / 스코핑

- 사용자 어휘 "페이지 또는 슬라이드(프레임)" = 페이지-바운드 flavor의 언어
  (doc-page의 페이지 / slide-deck의 슬라이드 — 내부적으로 frame). 규칙은
  `PAGE_AGENT_SURFACE`의 `pagePromptFragment`에만 추가; mixed/canvas-board의
  FREE_AGENT_SURFACE는 promptFragment 자체가 없고 자유 캔버스 의미론이라 제외.
- 이 규칙은 스키마/매퍼로 표현 불가한 **판단(judgment)** — 요청이 기존 콘텐츠를
  겨냥하는지는 자연어 해석이므로, 레버는 per-submit 주입되는 promptFragment
  (use-aku-agent의 pageLine)이다. WI-169가 도구 쪽(page.add → FULL_FRAME →
  동기 활성화)을 이미 닫았으므로, 모델이 page.add를 선택하기만 하면 나머지는
  레일 패리티가 보장한다.

## 변경

`pieces/agent-surface.ts` `pagePromptFragment` 활성-페이지 분기 끝에 기본 판단
규칙 1문 추가:

> 기본 판단 규칙: 요청이 기존 아이템·페이지의 수정/변경/삭제를 명시하거나 현재
> 페이지를 직접 가리키지 않는 한, 새 콘텐츠·디자인 요청은 새 페이지에서
> 작업합니다 — 스냅샷 기준 활성 페이지가 비어 있으면 그 페이지를 그대로 쓰고,
> 이미 콘텐츠가 있으면 weave.page.add 로 새 페이지를 만든 뒤 그 안에서
> 작업하세요. 기존 페이지의 콘텐츠 위에 겹쳐 추가하지 마세요.

- 빈-활성-페이지 엣지: promptFragment는 순수 함수라 문서 내용을 모름 → 규칙이
  "스냅샷 기준 비어 있으면 그대로 사용"으로 모델에게 스냅샷 확인을 위임.
- 빈-덱(degenerate host) 분기는 무변경 — 이미 page.add 우선 라우팅.

## 검증

- 단위: `pieces/agent-surface.test.ts` pagePromptFragment 블록에 2케이스 추가
  (활성 분기에 규칙 문구 존재 / 빈-덱 분기는 규칙 없음).
- 프롬프트-온리 변경이라 실제 판단 품질은 모델-사이드 — 라이브 프로브는 쿼터
  절약을 위해 생략(WI-169 프로브가 도구 체인은 이미 입증).

## 잔여 (수용)

- 모델이 규칙을 무시하고 기존 페이지에 겹쳐 추가할 가능성은 잔존(프롬프트
  레벨 규칙의 본질적 한계). 강제하려면 서버/도구-레벨 게이트가 필요하나,
  "수정 요청인지"의 판별 자체가 자연어 해석이라 도구로 내릴 수 없음.
