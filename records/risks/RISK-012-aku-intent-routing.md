# RISK-012 — 아쿠 의도 기반 파이프라인 라우팅

- 관련: WI-148, DR-102, FR-023
- 등급: MEDIUM (UX/품질 리스크 중심, 보안/법무 노출 없음 — 기존 공유 워크스페이스 모델 불변)

## R1 — 오분류로 잘못된 파이프라인 (MEDIUM)

의도 자동 추론은 확률적 → "수정"을 "추가"로, "팔레트만"을 "전면 재디자인"으로 오라우팅 가능.
- 완화: **하이브리드 보정칩**(1급 요건) + 명시 슬래시 + `intentSource: client/off`.
- 완화: 저확신 시 보정 묻기(임계값 설정), 보정칩은 항상 표시 옵션.
- 잔여: 자동 추론을 켠 한 0 불가 — 수용, 교정 경로로 흡수.

## R2 — 범위 한정 편집의 과편집 (MEDIUM)

"선택 아이템만 수정"·"recolor만"이 프롬프트 준수에 의존 → 에이전트가 다른 아이템/구조까지 변경 가능.
- 완화: operation 지시문 + 범위 리뷰 렌즈 + recolor 시 critique/prune/reflow OFF.
- 완화: 모든 편집은 여전히 `editor.exec`→History → 사용자가 Cmd+Z로 즉시 되돌림(History 계약).
- 잔여: 하드 보장 아님. 진짜 하드 가드(툴 스코프를 특정 itemId로 제한)는 **별도 범위**로 명시.

## R3 — 분류 지연 (LOW)

서버 모드는 빌드 전 분류 턴 1회 추가 → 첫 편집까지 지연.
- 완화: 빠른/저비용 모델·저토큰 분류, 명시 신호 시 생략, `client` 모드는 분류 턴 0.

## R4 — 지칭(referenced) 해소 모호성 (LOW)

"그 제목"이 여럿 매칭 → 엉뚱한 대상 편집.
- 완화: clarify 재사용 디스앰비규에이션("어느 제목인가요?"), 미해소 시 보정칩으로 폴백.

## R5 — 교차 프로젝트 스큐 / 와이어 호환 (LOW)

weave·small-think 동시 변경, 버전 스큐.
- 완화: `intent` 이벤트는 **additive**(미지 타입 tolerate), `client` 모드는 task 증강만으로 서버
  무변경 빌드에서 동작 → 클라이언트 선착륙. 서버는 명시 intent 없으면 기존 경로(회귀 없음).

## R6 — 설정 복잡도/인지 부하 (LOW)

`intentSource` 3-모드 + 임계값 토글이 사용자에게 과할 수 있음.
- 완화: 기본 `server`로 무설정 동작, 고급 토글은 기존 `AkuSettingsMenu` 패턴에 숨김(점진 노출).
